## 2026-04-21 19:25 · v0.5.1 · bug-fix · [traffic-light, tao-semantics, dom-center]

**Related**: worktree:.worktrees/v0.5.1-299177e4 · file:crates/nf-shell/src/webview.rs:23-49
**Session**: 32c1fbab-93bb-4767-bade-ad303cf41446

### 现状

前 session (299177e4) 在 v0.5.1 迭代 traffic light inset · HEAD commit `dc58b18f` 把 y 改成 `(48-14)/2=17`("历史验证 17 是唯一正解") · worktree 又把 y 改回 20 未 commit · 用户视觉反馈都不居中。

### 根因(读 tao 0.35 view.rs:1152-1182 源码得)

`with_traffic_light_inset(x, y)` y **不是** "button 距顶 padding"(Electron 式):

```rust
let title_bar_frame_height = close_rect.size.height + y;  // ← y 是容器高度"增量"
// button origin.x = x · origin.y **不动** · 靠 Cocoa 默认放置
```

→ y 的语义 = title_bar 容器额外高度 · button 在容器内由系统自动 placement。数学直觉 `(H-button_h)/2=17` 套错了公式 · 所以 17/20 都偏上。

### 正确公式(容器高度模型)

要 button 跟 **H=48px DOM titlebar** 垂直居中对齐:

```
y = H - button_h   // 让 title_bar_container 撑到 H 高 · 系统居中 button
             = 48 - 14 = 34
```

### 调研

查 zed / charrondev gist / ItsEeleeya tauri-plugin-trafficlights-positioner · 3 处都走**另一路** — 绕开 tao/tauri 封装 · objc2 挂 `NSWindowDelegate.windowDidResize` + `setFrameOrigin` 精准管 button 位置(resize/fullscreen/minimize 全覆盖)。tao drawRect-based inset 只保 resize · fullscreen 可能飘。

1. POC-A · 1 行改 y=34 cargo build → `nf capture` 截图 Read PNG 肉眼验容器公式对不对

## 2026-04-24 17:17 · v0.10.0 · Discuss · [export, performance, recorder, next-version]

**Session**: codex-2026-04-24-export-review

用户询问现有导出模式是否有优化空间。本次读代码链路后判断:
- 当前 `nf export` 会把 composition/episode compile 成 source JSON，再走 `nf_recorder::run_export_from_source`，每帧驱动同一套 runtime seek → CARenderer/IOSurface snapshot → VideoToolbox encode。
- CLI 目前硬编码 `resolution_override=1080p` 和 `parallel=1`，所以 v2 composition 导出没有使用 recorder 已存在的并行分片能力。
- `RecorderEventQuietGuard` 关闭了 recorder stdout JSONL 事件；shell `export.start` 又用 `Command::output()` 等进程结束，因此桌面端只能显示 running/succeeded/failed，拿不到真实帧进度。
- recorder 底层已有 `--parallel`、`record.encode_progress`、`record.parallel.*` 事件和 ffmpeg concat 分片架构；这是短期最高 ROI 优化入口。

建议下一版聚焦 export-performance:
- 给 `nf export` 暴露 profile/fps/resolution/parallel。
- 桌面端 export job 改为流式读取 stdout JSONL，聚合 percent/ETA，前端显示真实进度。
- 默认提供 draft(720p/30fps) 与 final(1080p/60fps) 两档；final 对长视频启用 2-4 并行 POC。
- 后续再做 component-level cache/static/render_fps，不能牺牲 HTML/CSS/SVG/JS 与预览一致性。
