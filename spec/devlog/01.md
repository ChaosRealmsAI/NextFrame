### A. agent vs workflow(Anthropic 原话)

| | workflow | agent |
|---|---|---|
| 谁决定下一步 | 代码(if/else / DAG) | LLM 自己 |
| 可预测性 | 高 | 低 |
| 成本 / 延迟 | 低(固定步) | 高(反复转) |
| 何时用 | 任务能拆固定步 | 任务开放 |

**口诀**:能画流程图 → workflow · 画不出来 → agent。**Anthropic 建议:先 workflow · 真做不到才上 agent**。

### B. 单 agent loop 骨架(就 20 行)

```
用户输入 ──► [LLM 想]──► tool_call? ──是─► 执行 tool ──► 塞回 context
                           │                          (回 LLM 想)
                           否(LLM 纯文本)
                           ▼
                        返用户 · 循环结束
```

Claude Code 叫 master loop · 本质一个 while 循环。复杂在 **augmented LLM**(LLM + 检索 + 工具 + 记忆)配置。

### C. 5 种 workflow 模式(Anthropic)

1. **Prompt Chaining** · `A ─► B ─► C`
2. **Routing** · `in ─► 分类 ─► {A|B|C}`
3. **Parallelization** · `in ─► {A ‖ B ‖ C} ─► 汇总`
4. **Orchestrator-Workers** · 主 LLM 动态拆 · 分派(接近 agent)
5. **Evaluator-Optimizer** · 生成+评审循环

### D. NextFrame 3 方案结论

| | A·固定 5 步 workflow | B·单 agent 全自主 | C·Orchestrator-Workers |
|---|---|---|---|
| 可预测 | 高 | 低 | 中 |
| 成本 | 低 | 高 | 中 |
| 适配 v1 | ✅ 最匹配 | ❌ 太飘 | ⚠️ 太早 |

**v1 = 方案 A(固定 workflow JSON→HTML→MP4)+ 每步内部小 agent loop**。质量瓶颈不在流程在每步内容 · agent 用在"选素材""写文案"这种步内小循环。**v2-v3** 某固定步规则写不清时升级为 agent loop · 其他仍 workflow。**v5+** 才考虑 C。

**核心一句**:agent 不是越自主越好 · Anthropic"先 workflow · 真做不到才上 agent"。混用 · 不是二选一。

这会让 agent **被锁死** · 无法:

- 某步失败回退重试
- 特殊场景偏离

### 正确 · 软 flow(playbook md 引导 · 非代码硬锁)

状态机 = **写进 `spec/prompts/{feature}-pipeline.md` 的软引导** · 不是 dispatcher gate。

# ✅ 所有 tool 可见 · flow 在 playbook
system_prompt = f"""
任务: {task}
可用工具: {ALL_23_TOOLS}   ← 全可见 · 不锁
推荐流程: {read('clips-pipeline.md')}   ← 读完自己走
自主性: 每步决策 + 步间可偏离
"""

def dispatch(tool_use):
    return run_tool(tool_use)   # 全放行
```

- **项目根 md**(`CLAUDE.md` / `NEXTFRAME.md` / `spec/prompts/clips-pipeline.md`)写规矩
- agent 读完按规矩做(自然遵守 · 不靠硬锁)
- 偶尔偏离 OK(场景需要)
- 每步自验靠 agent 主动调 `nf_verify` CLI 检产物 · 失败回头补

03 调研报告说"状态机式 guide md 每步对应 CLI · 内建 verify" → 我第一次理解成硬强制 · **实际 haiku 也是 soft flow**(prompt 引导 · 不是代码锁)。

- **flow 载体** = `spec/prompts/{feature}-pipeline.md`(playbook md)· 不在 dispatcher

### 架构细节

```
nf-agent <task> [--config PATH] [--skills-dir PATH] [--max-iters N]

流程:
1. 扫 --skills-dir 下 */SKILL.md · 头行 "# <name> · <desc>" 提取 enum
2. 构造 tools = [Bash, Read, LoadSkill(enum=<names>)]
3. 调 provider.chat(model, messages, tools) 进 while loop
4. tool_call 时 dispatch · 结果塞回 messages
5. 无 tool_call 或 max_iters → stop
6. 打印 stats JSON: iters/tokens/est_cost_usd
```
